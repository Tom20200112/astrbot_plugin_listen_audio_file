# 听音频文件（AstrBot 插件）

让 bot 能听群里/私聊里别人发的**音频文件**（mp3、m4a、wav、amr、flac、ogg 等，聊天里显示成一个文件的那种）和**语音条**。
听完它能说出里面是说话还是唱歌、逐句听写歌词、点评音准气息、判断男声女声，再用自己的话回你。

> AstrBot 本身看不到「文件」消息，你发个 mp3，bot 是完全不知道的；语音条最多被「语音转文字」转成文字，听不出唱得怎么样。这个插件补的就是这块。

---

## 一、准备

1. **AstrBot 4.x**，QQ 用 aiocqhttp（OneBot v11）接入，**NapCat 或 SnowLuma 都行**。在 AstrBot 4.28.1、4.28.2、4.29.0-beta.1 上测过。
2. **ffmpeg**：用官方 Docker 镜像部署的 AstrBot **已经自带**，不用管。
   自己装在 Linux 上的，跑一下 `sudo apt install ffmpeg`；Windows 要下载 ffmpeg 并加进 PATH。
   （没有 ffmpeg 的话，小于 7MB 的 mp3/wav 也能听，m4a 之类就不行了。）
3. **一个阿里云百炼的 API Key**（听音频用的是通义千问的 `qwen3.5-omni-flash` 模型）：
   1. 打开 <https://bailian.console.aliyun.com/>，用阿里云账号登录，按提示完成实名、开通百炼。
   2. 在控制台找到「API Key」页面，点「创建 API Key」，复制那串 `sk-` 开头的字符。
   3. 这串 Key 相当于你的钱包密码，**别发到群里、别截图给别人**。

   费用：按音频时长算，一首 4 分钟的歌大约用 2000 个 token，很便宜；新开通一般有免费额度，具体以百炼控制台显示为准。

## 二、安装

- **插件市场**：收录后，在 AstrBot 管理面板 →「插件」→ 插件市场里搜「听音频文件」安装。
- **从仓库地址装**：「插件」→「安装插件」→ 填 `https://github.com/Tom20200112/astrbot_plugin_listen_audio_file`。
- **从文件装**：从 [Releases](https://github.com/Tom20200112/astrbot_plugin_listen_audio_file/releases) 下载 zip，「安装插件」→「从文件安装」选它（不用解压）。

装好后插件列表里会出现 **「听音频文件」**。

## 三、填配置

1. 在「听音频文件」这张卡片上点 **「配置」**。
2. **「阿里云百炼 API Key」** 填上面复制的 `sk-...`，其他都不用改，点保存。
3. 如果之后听的时候报「HTTP 401」，就是 Key 填错了；报「HTTP 404 / 模型不存在」，把「接口地址」换成百炼控制台上给你的调用地址（以 `/compatible-mode/v1` 结尾）。**Key 会发到这个地址，别填不可信的。**

| 配置项 | 默认 | 说明 |
|---|---|---|
| 阿里云百炼 API Key | 空 | 必填 |
| 接口地址 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 一般不用改 |
| 听音频用的模型 | `qwen3.5-omni-flash` | 想听得更细可换 `qwen3.5-omni-plus`（更慢更贵） |
| 也能听语音条 | 开 | 收到语音条会在本地存一份副本；关掉就只管音频文件 |
| 最长听多少秒 | 600 | 超过的部分不听 |
| 收到音频文件或语音条就先存一份 | 开 | **建议开着**：QQ 文件的下载链接大约 13 小时就失效、群文件也常被删，语音条的临时文件 AstrBot 用完就删，先存一份以后才听得到 |
| 存的副本留几天 | 7 | 到期自动删 |
| 提醒 bot 最近有人发了音频 | 开 | bot 被叫到时，会知道最近 6 小时谁发过音频文件或语音条 |
| 允许从本机/内网地址下载音频 | 关 | **只在本机测试时打开**，平时开着的话，有人伪造链接就能让 bot 去访问你的内网 |

## 四、怎么用

- **最常用**：有人发了音频文件或语音条之后，@bot 说一句「听听刚才那首」「刚才那条语音唱得怎么样」。bot 会自己决定去听，然后回你。
- **指定听哪个**：**回复**那条音频文件或语音条并 @bot；或者说出文件名的一部分（「听听那个 hanser 的」）。
- **想让它重点听什么就直说**：「逐句听写歌词」「帮我听听音准和气息」「是男声还是女声」。
- **手动测试**：发 `/听音频`，会直接把最近一个音频文件或语音条的听感回出来（不经过 bot 的人设）。也可以写 `/听音频 逐句听写歌词`，或者回复某条音频再发。

**语音条和 AstrBot 自带的「语音转文字」是什么关系？** 打开「语音转文字」后，每条语音都会自动转成文字，bot 能看懂说了什么，但听不出唱得怎么样、是男声还是女声、语气如何。这个插件不自动听，bot 想细听或者有人让它听时才调工具。两个可以同时开，互不影响。

## 五、要知道的几件事

- 只记得**装好插件之后**发的音频；重启 AstrBot 后，「最近发了什么」的名单会清空（已经存下来的副本还在，回复那条消息就能找到）。
- 只是发个文件、不 @ 它，bot 不会主动去听（跟 AstrBot 平时的回复规则一样）。
- 语音条和音频文件的副本存在插件自己的数据目录里，超过「存的副本留几天」自动删除；只有被听的那一条才会发到阿里云百炼去识别，介意隐私的内容别让它听。
- 下载只走公网地址，跳转也逐跳检查，不会被引去访问本机、内网或云服务器的元数据地址。
- 听的结果是模型听出来的，歌名/原唱它经常猜错，插件已经提醒 bot 别说死。
- 如果 bot 用的大模型不支持工具调用（function calling），它就不会自己去听，只能用 `/听音频` 命令。
- 源码和问题反馈：<https://github.com/Tom20200112/astrbot_plugin_listen_audio_file>（提 issue 时附上日志里「听音频文件」那几行）。

## 六、出问题了看哪

AstrBot 面板的「控制台/日志」里搜 **「听音频文件」**，能看到它记下了哪些文件、下载或识别失败的原因。
